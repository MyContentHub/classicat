## 2. 体系文件的分类定义（结构性维度）

### 2.1 四层体系文件

体系文件固定分为四层（P00《文件控制程序》第 4 节原文：「体系文件分为四层:手册、程序文件、操作规范、表单」）：

| 层级 | 类别 | 定义 | 示例 | 审批权限 |
|---|---|---|---|---|
| 1 | 管理手册（方针文件） | 反映组织方针、目标，向组织内外部提供关于管理体系的信息文件 | 信息安全管理手册、信息安全适用性声明 | 管理运营部 / 管理者代表 |
| 2 | 程序文件 | 文件化的运作程序，是对完成管理活动所规定的方法 | 文件管理、记录管理、内审、风险管理等 22 个程序 | 管理运营部 / 各流程负责人 |
| 3 | 作业指导文件（操作规范） | 为保证具体作业活动符合要求而制订的作业标准 | 岗位职责说明书、网络安全规范、口令控制规范等 25 个 | 各流程负责人 |
| 4 | 记录、表单 | 为完成活动或达到的结果提供客观证据的文件，证明体系有效运行 | 目标考核表、巡检记录、备份记录等 83 项 | 各流程负责人 |

R01《ISMS 文件清单》中的实际类别名为：一级方针文件 / 二级程序文件 / 三级作业指导文件；第 4 级记录单独编入《ISMS 记录清单》。

### 2.2 文件编码规则

四段 14 位编码：`ZHKJ-ISMS-XNN-NNNN`

| 段 | 格式 | 含义 |
|---|---|---|
| 第 1 段 | `ZHKJ`（4 位字母） | 公司代号 |
| 第 2 段 | `ISMS`（4 位字母） | 管理体系 |
| 第 3 段 | `XNN`（3 位） | `X` = 体系阶层（M 手册 / P 程序 / W 作业指导 / R 记录）；`NN` = 流水号 |
| 第 4 段 | `NNNN`（4 位数字） | 年号 |

实际使用实例：`IS-M01`（手册）、`IS-P01~P22`（程序）、`IS-WI01~25`（作业指导）、`IS-R4-01`（记录）、`ZHKJ-ISMS-09`（表单模板）。

### 2.3 密级与文件管理属性的绑定

R01《文件清单》为每份文件登记：**文件类别 / 文件编号 / 版本 / 保存期限 / 保管部门 / 标识（受控）**。

- 保存期限按层级确定：1~3 级文件 3 年、记录 1 年
- 标识统一为「受控」
- 保管部门：总经办

## 3. 信息分类方法（保密性与风险维度）

### 3.1 密级分类（3 级）——《信息资产密级管理程序》

| 密级 | 定义 |
|---|---|
| 秘密 | 《保守国家秘密法》指定事项；或不可对外公开、泄露或被篡改会对公司日常经营造成**严重损害**、仅限有关人员知道的事项 |
| 敏感（受控） | 不可对外公开、泄露会造成损害；或仅向公司员工公开、不可向公司以外人员随意公开的事项 |
| 公开 | 秘密以外，仅用来传递信息、昭示承诺或对外宣传的事项 |

配套判定方法：

- **定密人**：部门经理级以上（含副经理）人员指定；员工无法判明时逐级请示
- **介质范围**：纸类、电磁类及其它媒体（纸张、软盘、硬盘、光盘、磁带、胶片）

### 3.2 信息资产价值分级（风险评估维度，C/I/A 各 5 级）

资产识别评价表模板（`01-信息资产识别评价表-模板.xlsx`）按三个安全属性分别赋值：

**保密性 C**：

| 级别 | 价值 | 分级描述 |
|---|---|---|
| 1 | 很低 | 可对社会公开的信息 |
| 2 | 低 | 组织/部门内公开，向外扩散可能造成轻微损害 |
| 3 | 中等 | 组织的一般性秘密，泄露会使安全和利益受到损害 |
| 4 | 高 | 组织的重要秘密，泄露会遭受严重损害 |
| 5 | 很高 | 最重要的秘密，泄露会造成灾难性损害 |

**完整性 I**：非常低（影响可忽略）→ 较低（轻微影响）→ 中等（明显影响）→ 较高（重大影响）→ 非常关键（业务重大中断，难以弥补）

**可用性 A**：可忽略（可用度<25%）→ 较低（≥25% 或中断<60 分钟）→ 中等（≥70% 或中断<30 分钟）→ 较高（≥90%/天 或中断<10 分钟）→ 非常高（年 99.9%+ 或不允许中断）

**资产重要性**：`R = C + I + A`（1–15）

| 等级 | 重要程度 |
|---|---|
| 1–3 | 不重要 |
| 4–6 | 不太重要 |
| 7–9 | 一般重要 |
| 10–12 | 重要 |
| 13–15 | 很重要 |

**重要资产判定标准**：R ≥ 4 的资产判定为重要资产，须实施有效控制。

### 3.3 密级与文件管理操作的绑定

- 发放：秘密文件发放需登记台账、指定接收部门和接收人
- 赔偿责任：泄漏秘密级别文件，泄密人赔偿全部损失、解除劳动合同、部门负责人降职 + 2000 元扣款；泄漏受控级别文件，通报批评 + 1000 元扣款

## 4. A.5.12 Classification of information（信息分类）对照分析

### 4.1 标准要求

组织应根据信息的保密性、完整性、可用性及相关方要求对信息进行分类。分类结果应随信息生命周期中的价值、敏感度和关键性的变化而更新；分类方案应与访问控制策略一致；组织间共享时应约定分类级别的解释程序。

### 4.2 目录中的相关材料

| 位置 | 内容 | 完整度 |
|---|---|---|
| `A512-信息分级/00-信息分级说明.txt` | ISO 27002:2022 控制指南完整中文翻译（政策、CIA+相关方要求、所有者负责、生命周期更新、组织间协议、过度/欠分类权衡） | ✅ 完整 |
| SoA（ISMS-M02） | A.5.12 标注**适用**，落地文件指向《信息资产密级管理程序》 | ✅ 有映射 |
| M01 附件1-职能分配表 | A.5.12 主责部门 = **信息化中心（▲）**，其余部门配合（△） | ✅ 有职责 |
| P00《信息资产密级管理程序》 | 3 级密级 + 定义 + 定密人 | ✅ 有落地 |
| 资产识别评价表模板 | C/I/A 各 5 级 + R=C+I+A | ✅ 有工具 |

### 4.3 与标准实施要点对照

| 27002 实施要点 | 落地情况 |
|---|---|
| 分类按 CIA + 相关方要求 | ✅ 资产模板按 C/I/A 三属性赋值；SoA 简述引用原文 |
| 信息所有者对分类负责 | ✅ A.5.9 资产清单指南明确所有者分类职责并定期审查 |
| 分类随生命周期更新 | ✅ A.512 说明.txt 覆盖；但落地程序中无复审周期 |
| 与访问控制策略一致 | ✅ SoA A.5.15 明确权限基于分类级别 |
| 组织间分类协议 | ⚠️ 仅标准指南文字，供应商/客户协议中未见落实 |
| 分类约定与审查标准 | ⚠️ 有分级定义，无「何时复审」的操作性规定 |

### 4.4 结论

A.5.12 **基本达标**：标准指南、SoA 映射、职责分配、两套分类方案（3 级密级 + C/I/A 5 级）齐全。短板在于复审机制未操作化。

## 5. A.5.13 Labelling of information（信息标记）对照分析

### 5.1 标准要求

应根据组织采用的信息分类方案，制定并实施适当的标记程序。程序应覆盖所有格式的信息及相关资产；可定义省略标记的例外；标记技术包括物理标签、页眉页脚、元数据、水印、图章；数字信息应利用元数据支持自动化处理（如 DLP）；应培训员工。

### 5.2 目录中的相关材料

| 位置 | 内容 | 完整度 |
|---|---|---|
| `A513-信息标记/00-信息标签.txt` | ISO 27002:2022 控制指南完整中文翻译 | ✅ 完整 |
| SoA（ISMS-M02） | A.5.13 标注**适用**，引用 a/b/c 例外情形，落地文件指向《信息资产密级管理程序》 | ✅ 有映射 |
| M01 附件1-职能分配表 | A.5.13 主责部门 = **信息化中心（▲）** | ✅ 有职责 |
| `A513-信息标记/P01-标签说明.docx` | **内容跑题**：实际为固定资产标签（条码、铭牌）说明，与信息标记无关 | ❌ 无效 |
| P00《信息资产密级管理程序》第 6 节 | 实际标记实践 | ⚠️ 覆盖不全 |

### 5.3 实际落地的标记方法

1. **纸质文件**：编写部门在封面标明「秘密」/「受控」
2. **电磁介质**：包装外部贴密级标签 + 内部存储文件名加注密级（双层控制）
3. **默认规则**：管理运营部发行的技术关联规程/集中管理规格书除特别指定外均属受控
4. **实例**：所有体系文件头部统一标注 `文档分类：内部公开 – 受控`（页眉标记的实际应用）

### 5.4 与标准实施要点对照

| 27002 实施要点 | 落地情况 |
|---|---|
| 覆盖所有格式的信息及资产 | ✅ 纸质 + 电磁介质均有规定 |
| 标记反映 5.12 分类方案 | ✅ 标记与密级绑定 |
| 物理标签 | ✅ 封面标注、介质贴签 |
| 页眉页脚 | ✅ 文档头部「内部公开 – 受控」 |
| 元数据标记 | ❌ 未落地 |
| 水印 / 图章 | ❌ 未落地 |
| 省略标记例外 | ✅ 公开信息无需标记 |
| 员工培训 | ❌ 标记程序中未体现 |
| 自动化处理（DLP 联动） | ❌ 未落地（SoA A.8.12 数据泄露防护一行落地文件为空） |

### 5.5 结论

A.5.13 **形式达标、实质薄弱**：标准指南原文与 SoA 映射齐全，但实际标记手段只有「封面标注 + 文件名加注 + 页眉标注」，27002 建议的元数据、水印、自动化联动均未落地。

## 6. 发现的缺口与不一致

| # | 问题 | 影响 | 建议 |
|---|---|---|---|
| 1 | **三套分类体系并存且无对应关系**：密级 3 级（秘密/敏感/公开）、资产价值 5 级（C/I/A）、文档标注「内部公开 – 受控」 | 员工无法判断三者如何映射，分类执行不一致 | 在安全文件管理规范中明确三者的适用范围与映射关系 |
| 2 | **术语混用**：第 3 层文件先后写作「操作指南」「作业指导文件」「操作规范」；「敏感」与「受控」交替使用；「分级」「分类」混用 | 同一概念多种称呼，审核时易被判不符合 | 统一一整套术语定义 |
| 3 | **A.5.13 落地不足**：SoA 声称由《信息资产密级管理程序》落地，但该程序未覆盖元数据/水印/自动化标记 | 认证审核高风险项；DLP 等自动化控制无法联动 | 补充电子文档元数据标记规范（如 Office 文档属性、DLP 策略联动） |
| 4 | **P01-标签说明.docx 内容跑题**：A513 文件夹内该文件实为固定资产标签说明 | 落地文件与条款错位 | 替换为真正的信息标记操作文件 |
| 5 | **分类复审机制缺失**：指南要求「分类结果随生命周期更新」，落地程序无复审周期 | 信息脱敏/升级后未重新标记 | 增加分类复审节点（如年度评审、变更触发复审） |
| 6 | **A.8.12 数据泄露防护落地文件为空**：SoA 该行落地文件栏为空白 | 与 A.5.13 元数据标记缺失互为因果 | 与标记规范一并补齐 |

## 7. 总体结论

1. **文件分类定义**：体系文件四层（手册/程序文件/操作规范/表单）定义清晰，编码规则、审批权限、保存期限均已落地；R01《文件清单》提供了完整的分类实例。
2. **分类方法**：存在三个维度——体系层级（4 层 + 编码）、密级（3 级）、资产价值（C/I/A 5 级 + R=C+I+A）；维度设计合理但**相互关系未打通**。
3. **A.5.12 信息分类**：材料完整，基本达标。
4. **A.5.13 信息标记**：标准参考材料完整，但落地仅有物理标记，缺元数据/自动化手段，且 A513 文件夹内的操作文件内容跑题——这是安全文件管理规范中**最需要补强的部分**。
